# 게임 데이 실험 시트

실험 1건당 시트 1장. 실험을 시작하기 전에 1~3번을 먼저 채운다 — 실험을 돌리고 나서
가설을 쓰면 게임 데이가 아니라 사후 합리화다.
절차는 책 『모범 사례 2판』 5.8의 4단계(가설 → 이벤트 → 대조 → 판정)를 따른다.

## 1. 정상 상태 가설

실험 전 30분간의 값을 기준으로 적는다. "무엇이 변하지 않아야 성공인가"까지 문장으로.

- 정상 상태 정의: (예: gateway P95 ≤ 120ms, 5xx 비율 ≤ 0.5%)
- 가설: (예: order-api 파드 1개가 죽어도 gateway 5xx 비율은 5%를 넘지 않는다)
- 판정 도구: (예: obs-red 대시보드 P95 패널, AppHighErrorRate 알림)

## 3. 대조군

- 실험 전 캡처: 대시보드 스크린샷 또는 질의 결과값 (시각 기록)
- 비교 지표: (예: 실험 전/중/후 각 5분 구간의 P95, 5xx 비율, restart 횟수)

## 6. 뒷정리 확인

- [ ] 카오스 리소스 삭제됨 (`kubectl -n chaos-mesh get podchaos,networkchaos` 비어 있음)
- [ ] 부하 생성 루프 종료함
- [ ] 발화했던 알림이 전부 해소(resolved)됨
- [ ] replicas 등 실험용으로 바꾼 값 원복함
