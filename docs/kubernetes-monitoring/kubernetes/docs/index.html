노트북 한 대에서 kind 클러스터를 세우고, 스프링 애플리케이션 두 개를 배포한 뒤, 프로메테우스·그라파나·로키로 관측하는 10단계 실습입니다. 각 문서는 그대로 따라 하면 동작하도록 명령과 매니페스트를 전부 포함합니다.

스터디 운영 제안

문서 10편을 8주에 한 편씩 배분하면 실패합니다. 02와 06에서 진도가 갈리기 때문입니다. 실제로 굴려보고 조정할 것을 전제로, 8주 기준 배분안을 제안합니다.

주차문서모임에서 할 것
1주00 · 01각자 preflight.sh 결과 공유 → 미달자 대응 결정. 클러스터 생성까지 함께
2–3주02계측 코드 리뷰. 라벨 값이 유한한지 서로 검증
4주03 · 04배포와 스택 설치. up == 0이 빈 결과인지 다 함께 확인
5주05대시보드 프로비저닝. 각자 만든 JSON을 저장소에 합치기
6–7주06 · 07PromQL 실습에 시간을 몰아준다. 알림 임계값은 관측 후 정한다
8주08 또는 10로그가 필요 없으면 08을 건너뛰고 10으로. 마지막에 "실습 → 운영" 표를 함께 읽는다
먼저 정해둘 것

메모리 12 GiB 미만인 사람이 셋 이상이면 워커 노드를 1개로 줄인 구성을 기본값으로 바꾸세요. 08단계(로키)는 여기에 2 GiB를 더 요구하므로, 그 경우 로그 단계만 공용 클러스터로 돌리는 편이 안전합니다. 진도가 갈리는 원인의 대부분은 이해도가 아니라 하드웨어입니다.

읽기 전 주의

  • 이 설정을 사내로 그대로 옮기지 마세요. 실습 속도를 위해 타협한 설정이 13가지 있고, 10단계 6절에 전부 정리돼 있습니다.
  • 버전은 반드시 재확인하세요. 이 시리즈를 쓰는 동안에도 차트는 여러 번 올라갔습니다. 문서에 박힌 숫자보다 helm search repo 출력이 우선입니다.
  • 명령은 검증했지만 실환경 실행은 각자의 몫입니다. YAML·PromQL·LogQL·셸·Java 문법은 파서로 확인했으나, 클러스터 동작은 하드웨어와 버전에 따라 달라집니다.
  • 부하 생성 루프를 끄는 것을 잊지 마세요. 06·07·08단계에 무한 루프가 등장합니다.
