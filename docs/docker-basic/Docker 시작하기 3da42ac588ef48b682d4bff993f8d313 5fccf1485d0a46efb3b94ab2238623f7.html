Docker 시작하기

컨테이너의 이해

어플리케이션의 라이브러리나 프레임웍들은 버전 관련 변경사항에 민감하고 보안 패치등 유지 관리 비용이 많이 든다.

반면에 컨테이너로 운영하게 되면 인프라 사용 자원의 효율성도 늘어나고 빠른 실행이 가능해지며, 불면한 실행 환경을 제공할 수 있다.

이라한 차이는 설정의 번거로움에도 한번 설정한 환경으로 개발 부터 리얼 환경까지 커버할 수 있게 됨으로서 이점이 존재하게 된다.

도커에서 NGINX 서버를 띄워보자.

도커 이미지 (nginx)를 다운로드 한다.

$ docker pull nginx

nginx 를 실행해본다.

$ docker container run --name webserver -d -p 8000:80 nginx

도커 이미지를 미리 다운로드 하지 않아도 RUN 명령어를 실행할 수 있다. (이미지가 없으면 다운로드를 진행한 후 명령어가 실행된다)

브라우저를 통해 detached mode (-d 옵션) 로 실행되고 있는 nginx를 실행한다는 명령어이고, 결과는 아래와 같다.

docker container run : 새로운 컨테이너 생성 및 실행

  • name webserver : 컨테이너의 이름을 지정
  • d : 백그라운드에서 컨테이너를 실행하며 컨테이너 ID를 출력
  • p 8000:80 : 컨테이너와 호스트OS 포트 번호(80)을 매핑시킴 (ex. -p 8000:80 입력 시 호스트OS 8000 과 컨테이너 80 을 매핑), 도커에서 실행되는 포트와 현재 호스트인 내 PC의 포트를 연결해준다.

정상적으로 실행 중이면 docker container ps 를 입력하여 컨테이너의 프로세스 상태를 확인할 수 있고, docker container stats webserver 를 입력하여 웹서버 컨테이너의 상태를 실시간으로 확인할 수 있다.

$ docker container stats webserver
$ docker container ps

제대로 실행되는지 브라우저를 통해 접근해보자.

정상적으로 실행된다면 webcome to nginx 라는 index 페이지를 볼 수 있을것이다.

  • 실행 : docker start webserver
  • 재실행 : docker restart webserver
  • 중지 : docker stop webserver

만약 도커 컨테이너를 삭제하려고 하면 rm 명령어로 처리할 수 있다.

$ docker rm [컨테이너 명 | 컨테이너 ID]

여기서는 docker rm webserver 라고 해주면 되는데, 만약 이미지가 실행중이라면 정지 후에 처리하라는 에러메세지가 나온다.

Error response from daemon: You cannot remove a running container 81a3ac57769d270ed3e31cd3dea89e0f35ba0fcd21fcf0173dcd31bcbd3b6a1a.
Stop the container before attempting removal or force remove

이럴때는 docker ps -a 로 실행중인 프로세스를 확인한 후 정지 (stop) 명령어로 처리 한 후 삭제하도록 한다.

만약, 도커 이미지를 삭제하고 싶다면 아래와 같이 입력하면 된다.

docker rmi [이미지 이름(repository) | Image ID]

$ docker rmi f0b8a9a54136
or$ docker rmi myserver

다시 docker images로 확인하면 리스트가 비어있음을 확인할 수 있다.

컨테이너 파일의 수정 (이미지 만들기)

nginx 의 index.html 문구를 변경해서 이미지를 만들어보자.

도커 내부의 파일을 수정한 후 이미지를 만들어야 한다. nginx 의 index.html 페이지 문구를 변경한 후 이미지를 만들면 된다.

nginx 에 접근하려면 호스트 머신에서 도커로 연결해야 한다. 터미널 환경으로 접속하기 위해서는 호스트 머신 (외부)에서 도커 컨테이너 (내부) 로 쉘을 실행해야 한다.

exec 명령어를 통해 nginx 내부 쉘을 실행해본다.

$ docker exec -it nginx /bin/bash

루트에서 찾으면 아래와 같은 경로가 나온다. (접근 권한이 없는 에러는 무시한다)

$ /usr/share/nginx/html/index.html

컨테이너 밖으로 나와 컨터이너의 내부 파일을 호스트 머신 (PC)로 복사해온다.

$ exit

$ docker cp webserver:/usr/share/nginx/html/index.html index.html

로컬에 본사된 index.html 을 vi 로 수정한다. (여기서는 welcome 메세지 영역을 hello world 로 수정했다.)

이제 수정된 index.html 파일을 다시 컨테이너로 복사한다.

$ docker cp index.html webserver:/usr/share/nginx/html/index.html

webserver 를 재시작하면 변경된 index.html 파일이 브라우저에서 확인될 것이다.

도커를 사용한 테스트 환경 구축

GCP 사용 설명이 필요한데, 여기서는 패스하도록 한다.

첫 사용자라면 정책상 얼마간의 무료 이용이 가능하니 구글 클라우드 플랫폼 문서를 활용해서 instance를 하나 만들어보도록 한다.

도커를 사용할 때 필요한 라이브러리

$ sudo apt install -y apt-transport-https ca-certificates curl gnupg2 software-properties-common

curl 명령어로 리포지토리의 GPG 키를 가져온다.

$ curl -fsSL [https://download.docker.com/linux/debian/gpg](https://download.docker.com/linux/debian/gpg) | sudo apt-key add

패키지 매니저에 도커를 설치할 수 있도록 해주는 리포지토리를 추가

$ sudo add-apt-repository "deb [arch=amd64] https://download.docker.com/linux/debian $(lsb_release -cs) stable"

패키지 매니저 업데이트

$ sudo apt update -y

도커 설치

$ sudo apt install docker-ce

일반 계정 유저도 도커를 사용할 수 있도록 권한 부여

$ sudo usermod -aG docker $USER

SpringBoot 설치

git에서 샘플을 다운받는다.

git clone https://github.com/ceo-nomadlab/docker.git

경로는 /home/사용자 계정/docker-sample/docker/target/docker-0.0.1-SNAPSHOT.jar 에 jar가 있음을 확인할 수 있다. docker 경로로 이동하여 아래의 Dockerfile 을 작성한다.

FROM openjdk:8-jdk-alpine

도커 빌드로 이미지를 만들자.

도커에서 호스트 서버의 파일을 컨테이너로 복사하고 싶다면 아래의 명령어로 가능하다.

$ docker cp 호스트파일 컨테이너명:복사위치/파일명

반대로 컨테이너의 파일을 호스트 서버로 복사하고 싶다면 다음의 명령어를 입력한다.

$ docker cp 컨테이너명:파일위치/파일명 호스트서버 디렉토리

위와 같은 명령어를 통해 호스트 서버와 컨테이너 사이에 파일을 이동시킬 수 있다.

하지만 이 경우 테스트 환경 구축 후 실 환경으로 이전한다거나 서버가 여러대가 되어 다시 배포해야 한다면 귀찮아질 수 있다. 이를 해결하기 위해 도커 레지스트리를 활용한다.

도커 레지스트리를 이용한 테스트 배포

도커 허브 사이트에서 레파지토리를 생성할수 있다. (public, private 선택 가능)

무료 사용자는 한개의 private 리포지토리만 사용할 수 있다.

https://hub.docker.com/repositories

먼저 도커 허브의 계정 정보로 로그인 한다.

$ docker login

Login with your Docker ID to push and pull images from Docker Hub. If you don’t have a Docker ID, head over to https://hub.docker.com to create one.

Username: my-accountId

Password:

Login Succeeded

docker tag 명령어를 통해 로컬의 도커 이미지를 업로드 할 수 있다.

docker tag 이미지명 도커허브 아이디/레포지토리 이미지명:태그

여기서는 custom-nginx 라는 이미지 저장소를 만들고 거기에 로컬에 작업한 mynginx 이미지를 푸시 할 예정이다.

푸시는 아래와 같은 형식으로 입력한다.

docker push [my-accountId]/custom-nginx:tagname
$ docker push my-accountId/custom-nginx

도커 사이트에서 업로드 된것을 확인할 수 있다.

스크린샷 2022-09-13 오후 2.46.23.png

저장소를 직접 구축해서 운영하는것이 일반적인 방법이다. (이관이나 정책으로 도커 허브가 막힐 경우)

도커 레지스트리 이미지를 다운로드 하여 컨테이너를 생성한다.

$ docker pull registry
$ docker run -d -p 5000:5000 --restart=always --name registry registry

그 다음 도커 이미지를 저장한 후 태깅 하고 완료되면 푸시한다.

$ docker pull ubuntu
$ docker image tag ubuntu localhost:5000/ubuntu
$ docker push localhost:5000/ubuntu

클라우드 원격지에 도커 레지스트리를 설치하고 로컬에서는 원격지에 있는 도커 이미지를 다운로드 할 수 있다. (GCP의 경우 VPC네트워크에서 해당 포트의 방화벽을 오픈해야 한다)

윈도우 환경에서는 Docker Engine 메뉴에서 insecure-registries 를 통해 클라우드 서버 외부 IP를 등록해주고, 리눅스의 경우 /etc/docker 디렉토리 안에 deamon.json 파일을 생성해서 그 안에 json 포맷으로 insecure-registries 를 추가해야 한다.

$ sudo vi /etc/docker/daemon.json{
    "insecure-registries" : ["172.31.6.239:5000"]
}

저장한 후 도커 서비스를 재시작한다.

$ sudo systemctl restart docker

다시 클라우드 레지스트리에서 로컬로 이미지를 다운로드 해보자.

$ docker pull 172.31.6.239:5000/ubuntu

정상적으로 다운로드 되는 것을 확인 할 수 있다.
