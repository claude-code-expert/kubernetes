1이론

1.1 세 문제, 세 도구

문제도구방식
환경마다 값이 다르다. 같은 앱을 여러 곳에 배포한다Helm템플릿 + 값. 차트를 패키지로 설치·업그레이드·롤백. 릴리스 이력을 클러스터에 저장
남의 매니페스트(또는 내 것)를 고치지 않고 덧씌우고 싶다Kustomizebase 위에 patch. 템플릿 없음. kubectl에 내장
누가 언제 무엇을 apply했는지 모르고, 파일과 클러스터가 어긋난다GitOps (Argo CD·Flux)Git을 원본으로 컨트롤러가 클러스터를 계속 맞춘다. 사람은 커밋만 한다

셋은 경쟁이 아니라 층이다. Helm이나 Kustomize가 "무엇을 만들지"를 정의하고, GitOps 컨트롤러가 그것을 "언제 누가" 적용할지를 맡는다. Argo CD는 Helm 차트도 Kustomize 디렉터리도 그대로 읽는다.

1.2 Helm 차트의 뼈대

파일역할
Chart.yaml이름·차트 버전(version)·앱 버전(appVersion). 차트 버전은 차트 변경마다, 앱 버전은 이미지 태그를 따라 올린다
values.yaml기본값. 환경별 파일(values-dev.yaml)이 이것을 덮어쓴다. --set이 그 위를 덮는다
templates/*.yamlGo 템플릿. {{ .Values.x }}, {{ .Release.Namespace }}, {{ include … | sha256sum }}
templates/NOTES.txt설치 후 출력할 안내
crds/CRD. Helm은 설치만 하고 업그레이드·삭제하지 않는다(D10에서 본 kps의 한계)

Helm은 렌더링한 결과와 릴리스(설치 기록)를 네임스페이스의 시크릿(sh.helm.release.v1.…)에 저장한다. helm history가 그 시크릿을 읽고, rollback은 옛 렌더 결과를 다시 적용한다. D7의 설정 해시 스크립트는 템플릿 한 줄(checksum/config 어노테이션에 sha256sum)이 된다.

1.3 Kustomize: 템플릿 없이 덧씌우기

Kustomize는 완성된 YAML(base)을 그대로 두고 그 위에 patch를 얹는다. kustomization.yaml에 리소스 목록과 변환(이미지 태그 교체, 라벨 추가, 네임스페이스 지정, 패치)을 적고 kubectl apply -k로 적용한다. 템플릿 문법이 없어 base 자체가 유효한 YAML이라는 것이 장점이고, 조건문·반복문이 없어 "값 하나로 리소스 개수를 바꾸는" 일은 못 하는 것이 한계다. 선택 기준: 배포판을 남에게 나눠 주거나(패키지) 값이 수십 개면 Helm, 내 것 하나를 환경 셋으로 갈라 놓을 뿐이면 Kustomize. 둘을 겹쳐 쓰기도 한다(Helm 렌더 → Kustomize 패치).

1.4 배포 전략과 카나리

전략방식필요한 것
롤링새 파드를 하나씩 늘리고 옛 것을 줄인다(D4)Deployment만
블루/그린새 버전을 통째로 띄우고 트래픽을 한 번에 전환디플로이먼트 2벌 + 라우트 전환
카나리새 버전에 트래픽 일부만 보내며 지표를 보고 늘린다디플로이먼트 2벌 + 가중치 라우팅(D6) + RED 지표(D11)

카나리의 판정 기준은 사람이 정한다. "카나리의 오류율이 안정 버전의 2배를 넘거나 p95가 1.5배를 넘으면 중단". 오늘은 손으로 값을 올리고 대시보드를 보며 판정한다. 이것을 자동화한 것이 Argo Rollouts·Flagger 같은 프로그레시브 딜리버리 도구다.

1.5 GitOps 네 원칙

  1. 선언적 — 원하는 상태 전체가 파일로 표현된다(D3부터 해 온 것).
  2. 버전 관리 — 그 파일이 Git에 있다. 변경 이력·리뷰·되돌리기가 Git의 것이다.
  3. 자동 반영 — 승인된 변경은 사람이 apply하지 않아도 클러스터에 간다.
  4. 지속적 조정 — 컨트롤러가 Git과 클러스터를 계속 비교해 어긋나면(드리프트) 되돌린다. D2의 조정 루프가 Git 층에 하나 더 생긴 것이다.

Argo CD는 클러스터 안에서 돌며 Git 저장소를 주기적으로 읽어(pull) 렌더링하고 비교하고 적용한다. CI가 클러스터 자격 증명을 가질 필요가 없다. CI는 이미지를 빌드해 푸시하고 Git의 값 파일(태그 한 줄)을 갱신하는 것으로 끝난다. 시크릿은 Git에 평문으로 넣지 않는다. 암호화해 넣거나(SOPS), 외부 비밀 저장소에서 클러스터로 가져오는 컨트롤러(External Secrets Operator)를 쓴다. 오늘은 시크릿을 Git 밖에 두고 이름으로만 참조한다.

# week1 파일을 templates/ 로 복사하며 치환 — 이 스크립트가 '차트화' 그 자체다
$ cat > chartify.py <<'EOF'
import re, pathlib, shutil
src = pathlib.Path.home()/'k8s-study'/'week1'
dst = pathlib.Path('charts/study-app/templates')
keep = ['10-','13-','14-','15-','16-','20-','21-','22-','23-','24-','30-','41-','42-','50-','52-','60-','61-']
for f in sorted(src.glob('*.yaml')):
    if not any(f.name.startswith(k) for k in keep): continue
    t = f.read_text()
    if f.name.startswith('52-'):   # Prometheus 규칙의 {{ $value }} 는 Helm 템플릿과 충돌한다 → 이스케이프
        t = t.replace('{{', '\x00').replace('}}', '\x01')
        t = t.replace('\x00', '{{ "{{" }}').replace('\x01', '{{ "}}" }}')
    t = t.replace('namespace: study', 'namespace: {{ .Release.Namespace }}')
    t = t.replace('image: order-api:v6', 'image: {{ .Values.orderApi.image }}:{{ .Values.orderApi.tag }}')
    t = t.replace('image: gateway:v2', 'image: {{ .Values.gateway.image }}:{{ .Values.gateway.tag }}')
    t = t.replace('STORE_NAME: study-store-v2', 'STORE_NAME: {{ .Values.config.storeName | quote }}')
    t = t.replace('region: incheon', 'region: {{ .Values.config.region | quote }}')
    t = t.replace('release: kps', 'release: {{ .Values.monitoring.release }}')
    t = re.sub(r'config-hash: ".*"', 'checksum/config: {{ include (print $.Template.BasePath "/10-order-api-config.yaml") . | sha256sum }}', t)
    t = t.replace('minReplicas: 2', 'minReplicas: {{ .Values.orderApi.hpa.min }}')
    t = t.replace('maxReplicas: 8', 'maxReplicas: {{ .Values.orderApi.hpa.max }}')
    t = t.replace('averageUtilization: 50', 'averageUtilization: {{ .Values.orderApi.hpa.cpu }}')
    t = t.replace('replicas: 2\n', 'replicas: {{ .Values.gateway.replicas }}\n') if f.name.startswith('30-') else t
    t = t.replace('weight: 90', 'weight: {{ sub 100 .Values.canary.weight }}').replace('weight: 10', 'weight: {{ .Values.canary.weight }}')
    (dst/f.name).write_text(t)
    print('templated', f.name)
EOF

읽을 것 — 열일곱 파일 중 실제로 치환된 곳은 십여 군데뿐이다. 나머지 줄은 그대로다. checksum/config 한 줄이 D7의 스크립트 전체를 대신한다. 52번 규칙 파일의 {{ $value }}는 Prometheus의 템플릿 문법이라 Helm이 자기 것으로 오해하고 실패한다. 그래서 그 파일만 {{ "{{" }}로 이스케이프했다. Helm 차트에 Prometheus 규칙이나 Grafana 대시보드를 넣을 때 늘 만나는 문제다. 컨피그맵 템플릿의 렌더 결과를 해시해 어노테이션에 넣으므로 값이 바뀌면 해시가 바뀌고 롤링이 일어난다. {{ sub 100 .Values.canary.weight }}처럼 템플릿에서 계산도 한다.

2카나리 디플로이먼트를 템플릿으로 만든다

D6의 카나리(v1)는 프로브도 설정도 DB도 없다. 안정 버전과 같은 스펙에 이미지 태그만 다른 것이 진짜 카나리다. order-api 템플릿에서 파생시킨다.

$ python3 - <<'EOF'
import pathlib, re
d = pathlib.Path('charts/study-app/templates')
src = (d/'20-order-api-deploy.yaml').read_text()
t = src.replace('name: order-api\n', 'name: order-api-canary\n', 1)
t = t.replace('app: order-api\n', 'app: order-api-canary\n')          # labels, selector, template, topologySpread
t = t.replace('{{ .Values.orderApi.tag }}', '{{ .Values.canary.tag }}')
t = re.sub(r'(?m)^  replicas: \d+\n', '', t)
t = t.replace('spec:\n  selector:', 'spec:\n  replicas: 1\n  selector:', 1)   # 카나리는 HPA 대상이 아니다
t = '{{- if .Values.canary.enabled }}\n' + t.rstrip() + '\n{{- end }}\n'
svc = '''{{- if .Values.canary.enabled }}
---
apiVersion: v1
kind: Service
metadata:
  name: order-api-canary
  namespace: {{ .Release.Namespace }}
  labels:
    app: order-api-canary
spec:
  selector:
    app: order-api-canary
  ports:
  - name: http
    port: 8080
    targetPort: 8080
---
apiVersion: monitoring.coreos.com/v1
kind: ServiceMonitor
metadata:
  name: order-api-canary
  namespace: {{ .Release.Namespace }}
  labels:
    release: {{ .Values.monitoring.release }}
spec:
  selector:
    matchLabels:
      app: order-api-canary
  endpoints:
  - port: http
    path: /actuator/prometheus
    interval: 15s
{{- end }}
'''
(d/'22-order-api-canary.yaml').write_text(t + svc)
print(open(d/'22-order-api-canary.yaml').read()[:300])
EOF
$ grep -n 'replicas\|order-api-canary' charts/study-app/templates/22-order-api-canary.yaml | head -8

읽을 것 — 카나리 디플로이먼트는 안정 버전과 동일한 프로브·리소스·securityContext·설정 주입을 갖고 이름·라벨·태그만 다르다. {{- if .Values.canary.enabled }}로 통째로 켜고 끈다. 카나리 서비스에 app: order-api-canary 라벨과 http 포트 이름을 넣고 ServiceMonitor를 붙였으니 D11 대시보드에 job="order-api-canary"가 따로 뜬다. HPA와 PDB는 안정 버전에만 있다.

읽을 것 — 손으로 5로 올린 것이 20초 안에 2로 돌아왔다(selfHeal). Git에 커밋하자 3분 안에(기본 폴링 주기) 클러스터가 바뀌었다. 기다리기 싫으면 UI의 Refresh/Sync나 argocd app sync. 이제 클러스터를 바꾸는 유일한 방법은 커밋이고, 누가 언제 무엇을 바꿨는지는 git log다. prune: true는 Git에서 지운 리소스를 클러스터에서도 지운다. D7에서 말한 apply -f dir/의 세 한계가 전부 해소됐다.

Flux와의 차이

Flux는 같은 일을 UI 없이 CRD(GitRepository·Kustomization·HelmRelease)만으로 한다. Helm 차트를 실제 Helm 릴리스로 설치해 helm list에 보이는 것, 멀티테넌시 모델이 다르다. 팀에 UI가 필요하면 Argo CD, 전부 코드로 두고 싶으면 Flux. 원칙 네 가지는 같다.

4체크포인트

  1. helm template으로 dev와 prod의 렌더 결과 차이를 diff로 보이고, 왜 checksum이 다른지 말한다.
  2. 값 하나를 바꿔 업그레이드한 뒤 helm rollback으로 되돌리고 history에서 세 리비전을 읽는다.
  3. 카나리 가중치를 10 → 50으로 올리며 대시보드에서 두 job의 오류율을 비교해 진행/중단을 말하고, 0으로 되돌린다.
  4. Kustomize overlay로 이미지 태그와 HPA 상한을 바꾼 렌더 결과를 보인다.
  5. Git에 values 한 줄을 바꿔 push하면 Argo CD가 동기화하고, 손으로 scale한 값이 되돌아간다.

5개 중 4개 이상이면 D14로 간다. 5번이 막히면 Argo CD UI에서 Application의 Events와 저장소 연결 상태를 본다.
