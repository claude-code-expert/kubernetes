이 환경의 전제 (발표 시 명시)

LoadBalancer가 localhost로 열리는 것과 Gateway에 주소가 자동으로 붙는 것은 Docker Desktop 내장 kind의 편의 기능이다. kind CLI 단독, OrbStack, 클라우드 클러스터에서는 cloud-provider-kind·MetalLB·클라우드 LB가 따로 필요해 D5·D6의 접속 경로가 달라진다. 기존 관측성 실습 시리즈(kind CLI 기준)와 병행하는 참가자는 이 차이를 먼저 확인한다.

NetworkPolicy(D12)는 kind 기본 CNI(kindnet)가 집행하지 않는다. 매니페스트 작성과 개념까지 다루고, 집행 확인은 Cilium 설치를 선택 실습으로 둔다.

외부에서 들어오는 길 — 인그레스의 현재 위치와 Gateway API

서비스는 L4다. 경로와 호스트로 나누는 L7 라우팅은 Gateway API가 맡는다. Ingress 리소스는 기능 동결 상태이므로 신규 구성은 Gateway·HTTPRoute로 만든다.

이론

  • L4(서비스)와 L7(경로·호스트 라우팅)의 차이
  • Ingress 리소스 구조와 컨트롤러 의존성, 왜 동결됐나
  • Gateway API 역할 분리: GatewayClass(인프라) · Gateway(진입점) · HTTPRoute(앱)
  • Envoy Gateway 구조: 컨트롤 플레인 + 데이터 플레인 파드
