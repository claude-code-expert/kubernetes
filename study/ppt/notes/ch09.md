## 09-01 지금 설정은 노트북용이다

**도판** — `figures/ch09-fig1.svg` (00장 목표 구조가 완성된 그림)
**화면** — 실습 vs 운영 대비 표 · `tables/09-01-lab-vs-prod.tsv`

**말할 것**

먼저 **00장에서 그렸던 목표 구조가 그대로 완성됐다**는 것을 보여 준다.
화살표 방향 — 메트릭은 당겨오고 로그는 밀어 넣는다 — 도 그때 예고한 그대로다.

그런데 여기까지 만든 스택은 **한 사람이 노트북에서 돌리는 것을 전제**로 설정돼 있다.

- 보존 기간이 짧다 (`retention: 3d`)
- 복제본이 없다
- 인증이 열려 있다
- 자원 제한이 헐겁다

**그대로 운영에 올리면 대부분 첫 주에 문제가 난다.**

**현재 상태를 숫자로 남긴다** — 뒤 절의 비교 기준이 된다.

```
prometheus_tsdb_head_series                          → 현재 시계열 수
rate(prometheus_tsdb_head_samples_appended_total[5m]) → 초당 저장 샘플 수
```

실습 규모라면 시계열 3만~8만, 초당 샘플 500~2000 정도가 나온다.

## 09-02 프로메테우스를 죽이는 것은 트래픽이 아니다

**도판** — `figures/ch09-fig2.svg`

**말할 것**

프로메테우스를 죽이는 가장 흔한 원인은 트래픽이 아니라 **시계열 개수**다.
라벨 하나에 사용자 ID 나 요청 URL 같은 값이 들어가면 시계열이 수만 개로 늘고 메모리가 터진다.

**곱셈이라는 점이 무섭다.** 라벨 값의 조합만큼 시계열이 생긴다.

**02장에서 켠 `percentiles-histogram` 도 여기에 기여한다.**
02-04 에서 "공짜가 아니다"라고 한 대가를 여기서 치른다.

**이미 막아 둔 장치가 있다** — 02장에서 `@PathVariable` 로 매핑해
`uri` 가 `/api/orders/{id}` 로 찍히게 한 것이 바로 이 사고를 막는 장치였다.
직접 문자열을 파싱해 라우팅했다면 **주문 ID 가 그대로 라벨이 됐을 것이다.**

**고치는 순서** — 애초에 안 붙이는 것이 첫째,
이미 붙었다면 `metricRelabelings` 로 **스크레이프 시점에** 잘라내는 것이 둘째.
저장한 뒤에 지우는 것은 훨씬 비싸다.

## 09-03 느낌으로는 못 고친다

**화면** — tsdb 상태 질의 출력 · `snippets/output/09-03-cardinality.txt`

**말할 것**

**"무겁다"는 느낌으로는 고칠 수 없다.** 현재 시계열 개수 · 스크레이프 대상 수 ·
디스크 사용량을 먼저 질의해 **숫자로 만든 다음**, 어느 메트릭이 상위를 차지하는지 찾아 잘라낸다.

진단 질의 셋을 순서대로 던진다.

```
# ① 시계열을 가장 많이 차지하는 메트릭 10개
topk(10, count by (__name__) ({__name__=~".+"}))

# ② 특정 라벨이 몇 종류의 값을 갖는지 — 계속 늘면 위험 신호
count(count by (uri) (http_server_requests_seconds_count))

# ③ 스크레이프 대상별로 몇 개의 시계열을 만드나
topk(10, count by (job, instance) ({__name__=~".+"}))
```

②가 특히 실용적이다. 배포할 때마다 이 숫자를 재면 **카디널리티가 늘어나는 순간**을 잡는다.

## 09-04 간격 · 보존 · 디스크는 한 덩어리

**화면** — 삼각형 (`gaps.figure` — 새로 그려야 함)

**말할 것**

- 스크레이프 간격을 줄이면 해상도가 오르지만 디스크와 메모리가 함께 는다
- 보존 기간을 늘리면 과거를 볼 수 있지만 같은 대가를 치른다

**셋 중 둘을 정하면 나머지 하나가 결정된다.**
그러므로 **무엇을 포기할지를 먼저 정하고 숫자를 넣는다.**

거꾸로 하면 — "일단 15초 간격에 30일 보존"으로 시작해서 디스크가 터지고,
그때 급하게 보존을 줄이며 이미 필요했던 데이터를 잃는다.

**길게 보관해야 하면** 프로메테우스의 보존을 늘리는 대신 원격 저장소로 내보낸다.
로컬 디스크를 키우는 방향은 한계가 빨리 온다.
