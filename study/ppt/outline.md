# 장표 아웃라인

정본은 `study/ch*.html` 열한 편이다. 이 아웃라인은 거기서 뽑은 것이고,
둘이 어긋나면 **문서를 기준으로 이 파일을 고친다.**

장표마다 네 줄이다.

| 줄 | 무엇 |
|---|---|
| 제목 | 명사구가 아니라 **주장**으로 |
| 화면 | 그 장표에 띄울 것 (도판·표·코드·출력) |
| 말할 것 | 한 문장. 두 문장을 넘으면 장표를 쪼갠다 |
| 넘어가며 | 다음 장표로 잇는 한 마디 |

총 56장표. 장당 3~8장표이고, 발표 시간은 장표 하나에 90초를 기준으로 잡는다.

---

## 00 · 환경과 버전 고정

실습 문서: [`ch00-setup-versions.html`](../ch00-setup-versions.html) · 장표 6개

### 00-01 왜 버전을 고정하나

- **화면** — 8명이 같은 화면을 보려면 같은 숫자여야 한다
- **말할 것** — 스터디 6주 동안 차트는 3~4번 올라간다. 한 사람이 88.3.0으로, 다른 사람이 90.x로 설치하면 대시보드 JSON이 서로 맞지 않는다
- **넘어가며** — 그래서 첫 장에서 코드를 한 줄도 쓰지 않는다

### 00-02 메트릭이 이상을 알려주고, 로그가 이유를 말해준다

- **화면** — 좌우 두 칸 · 지연 그래프 / 로그 한 줄
- **말할 것** — 메트릭은 '지금 이상하다'까지만 안다. 왜 이상한지는 그 시각의 로그에 있다
- **넘어가며** — 이 시리즈의 04~07이 메트릭, 08이 로그다

### 00-03 폐쇄형과 개방형

- **화면** — 앱 바깥에서 보는 것과 안에서 보는 것
- **말할 것** — CPU·메모리는 앱이 왜 그렇게 동작하는지 맥락을 주지 못한다
- **넘어가며** — 02장에서 앱 안에 계측을 심는 이유

### 00-04 메트릭은 당겨 오고 로그는 밀어 보낸다

- **화면** — 화살표 방향이 반대인 그림 한 장
- **말할 것** — 프로메테우스는 대상의 /metrics 를 긁어 온다. 로그는 수집기가 로키로 밀어 넣는다
- **넘어가며** — 이 차이가 04장 ServiceMonitor 와 08장 Alloy 설정의 생김새를 가른다

### 00-05 버전 매트릭스

- **화면** — 표 · 7행
- **말할 것** — 검증일과 함께 적는다. 실습 당일 재확인
- **넘어가며** — 다음 장에서 이 숫자로 클러스터를 만든다

### 00-06 사전 점검

- **화면** — preflight.sh 실행 결과 · 판정 줄만
- **말할 것** — 여기서 막히면 다음 장이 전부 막힌다
- **넘어가며** — 통과했으면 클러스터를 만든다

## 01 · kind 클러스터 구축

실습 문서: [`ch01-kind-cluster.html`](../ch01-kind-cluster.html) · 장표 4개

### 01-01 설정 파일 20줄이 승부처

- **화면** — 기본 설정 클러스터 vs 설정한 클러스터 — 타깃 4개 차이
- **말할 것** — 기본 설정으로 만들면 04장에서 controller-manager·scheduler·etcd·kube-proxy 가 DOWN 이다
- **넘어가며** — 이유는 127.0.0.1 에만 바인드하기 때문이다

### 01-02 만든 뒤에는 못 고친다

- **화면** — 시간축 · 지금 20줄 vs 나중에 노드 진입
- **말할 것** — 클러스터를 만든 뒤 바꾸려면 컨트롤 플레인 노드에 들어가 매니페스트를 고치고 재시작해야 한다
- **넘어가며** — 비교할 수 없이 싸다

### 01-03 맥에서 포트가 흐르는 경로

- **화면** — 호스트 → VM → 노드 컨테이너 → 파드 네 칸
- **말할 것** — 네 칸을 전부 뚫어야 브라우저에서 그라파나가 열린다
- **넘어가며** — port-forward 는 끊긴다. extraPortMappings 를 쓴다

### 01-04 클러스터 생성과 검증

- **화면** — kind create 명령 · nodes 출력 판정 줄
- **말할 것** — STATUS 가 전부 Ready
- **넘어가며** — 이제 앱을 만든다

## 02 · 계측 가능한 애플리케이션

실습 문서: [`ch02-instrumented-app.html`](../ch02-instrumented-app.html) · 장표 6개

### 02-01 파드는 오래 살지 않는다

- **화면** — VM 24시간 vs 파드 수명 그래프
- **말할 것** — 개별 인스턴스를 추적하는 방식은 성립하지 않는다. 레이블로 묶은 집합을 본다
- **넘어가며** — 무엇을 측정할지부터 정한다

### 02-02 USE 와 RED

- **화면** — 표 2행 · 인프라 / 애플리케이션
- **말할 것** — USE 는 사용률·포화도·에러, RED 는 처리율·에러·처리시간
- **넘어가며** — 스택 내장 대시보드가 USE 를, 우리가 심는 계측이 RED 를 채운다

### 02-03 평균 40ms 뒤에 숨은 3초

- **화면** — 분포 그래프 · 평균선과 P99 선
- **말할 것** — 99건이 10ms, 1건이 3초면 평균은 40ms 다. 대시보드는 초록이고 그 1건은 이탈한다
- **넘어가며** — P99 를 보려면 히스토그램 버킷이 필요하다

### 02-04 분위수는 공짜가 아니다

- **화면** — percentiles-histogram 켜기 전후 시계열 수
- **말할 것** — 켜는 순간 시계열이 버킷 개수만큼 는다
- **넘어가며** — 09장에서 카디널리티 문제로 돌아온다

### 02-05 요청 하나가 만드는 세 종류

- **화면** — HTTP · JVM · 도메인 지표
- **말할 것** — 세 번째가 이 실습의 핵심이다
- **넘어가며** — orders.created · rejected · processing · stored

### 02-06 이 네 이름을 바꾸지 않는다

- **화면** — 의존 관계 화살표 · 06 PromQL, 07 대시보드
- **말할 것** — 마이크로미터가 점을 밑줄로 바꿔 orders_created_total 로 노출한다
- **넘어가며** — 이제 컨테이너로 만든다

## 03 · 컨테이너화와 배포

실습 문서: [`ch03-containerize-deploy.html`](../ch03-containerize-deploy.html) · 장표 6개

### 03-01 docker images 에 보여도 파드는 안 뜬다

- **화면** — 두 개의 저장소 그림
- **말할 것** — 도커 데몬의 저장소와 kind 노드 안 런타임 저장소는 다른 공간이다
- **넘어가며** — kind load 가 그 간극을 메운다

### 03-02 적재 확인은 노드 안에서

- **화면** — crictl images 출력 · 판정 줄
- **말할 것** — docker images 로는 알 수 없다
- **넘어가며** — 여기서 확인하고 넘어간다

### 03-03 latest 를 쓰면 조용히 깨진다

- **화면** — imagePullPolicy 기본값 표
- **말할 것** — latest 면 Always 가 되어 적재해 둔 이미지를 무시하고 ErrImagePull
- **넘어가며** — 모든 이미지에 버전 태그를 박는다

### 03-04 프로브 세 개가 답하는 서로 다른 질문

- **화면** — 표 3행 · 실패하면 무엇이 일어나나
- **말할 것** — startup 은 미루고, readiness 는 빼고, liveness 는 죽인다
- **넘어가며** — 기동 느린 앱에 liveness 만 걸면 CrashLoopBackOff

### 03-05 이미지 크기 — Dockerfile 네 개

- **화면** — 1.02GB → multi 비교 막대
- **말할 것** — naive 는 JDK·메이븐·소스가 전부 남는다
- **넘어가며** — 외부 docker-sample 로 재현한다

### 03-06 배포와 검증

- **화면** — rollout status · describe 이벤트
- **말할 것** — 뜨지 않으면 이벤트부터 읽는다
- **넘어가며** — 이제 관측 스택을 올린다

## 04 · 프로메테우스 스택 설치

실습 문서: [`ch04-prometheus-stack.html`](../ch04-prometheus-stack.html) · 장표 5개

### 04-01 메모리 사용량이 왜 두 군데서 다른가

- **화면** — 네 출처 그림
- **말할 것** — cAdvisor · metrics-server · node-exporter · kube-state-metrics
- **넘어가며** — 말로 구분하지 말고 직접 질의해서 나온 이름으로 구분한다

- **화면** — node-exporter vs KSM 대비

- **화면** — 시간축 · 현재값만

### 04-04 오퍼레이터는 스크레이프하지 않는다

- **화면** — 오퍼레이터 → 설정 → 프로메테우스 본체
- **말할 것** — 오퍼레이터는 CR 을 읽어 설정을 만들어 줄 뿐이다
- **넘어가며** — 06장에서 타깃이 안 잡힐 때 어느 쪽을 볼지가 여기서 갈린다

### 04-05 타깃 검증이 이 장의 핵심

- **화면** — targets API 출력 · 판정 줄
- **말할 것** — 01장 설정이 여기서 결과로 나온다
- **넘어가며** — 다음은 그 데이터를 보는 화면이다

- **넘어가며** — 카디널리티가 1번 사망 원인

### 09-03 느낌으로는 못 고친다

- **화면** — tsdb 상태 질의 출력 · 상위 메트릭
- **말할 것** — 현재 시계열 수를 먼저 숫자로 만든다
- **넘어가며** — 그다음 metricRelabelings 로 스크레이프 시점에 잘라낸다

### 09-04 간격·보존·디스크는 한 덩어리

- **화면** — 삼각형 · 둘을 정하면 하나가 결정된다
- **말할 것** — 무엇을 포기할지 먼저 정하고 숫자를 넣는다
- **넘어가며** — 마지막으로 이 체계가 쓸모 있는지 확인한다

## 10 · 테스팅과 카오스 실험

실습 문서: [`ch10-chaos-testing.html`](../ch10-chaos-testing.html) · 장표 8개

### 10-01 쓸모 있는지 아는 유일한 방법

- **화면** — 이상을 일부러 만든다
- **말할 것** — 07장 알림이 우는지, 05장 대시보드가 보여 주는지 판정한다
- **넘어가며** — 가설을 먼저 쓰고 실험을 나중에 돌린다

### 10-02 게임 데이 네 단계

- **화면** — 가설 → 이벤트 → 대조 → 판정
- **말할 것** — 실험 후에 가설을 쓰면 게임 데이가 아니라 사후 합리화다
- **넘어가며** — 시트 1~3번을 실험 전에 채운다

### 10-03 폭발 반경 최소화

- **화면** — 파드 1개 · 네임스페이스 하나 · 5분
- **말할 것** — 라벨로 지우면 매칭되는 파드가 전부 죽는다. 이름을 골라 하나만
- **넘어가며** — 첫 실험은 손으로 한다

### 10-04 책과 달라진 것

- **화면** — Chaos Toolkit 0.39.0(2024-04) 이후 릴리스 없음
- **말할 것** — Chaos Mesh 를 쓴다. 실험이 CR 로 저장소에 남는다
- **넘어가며** — 재현성이 여기서 갈린다

### 10-05 설치 성공과 동작함은 다르다

- **화면** — 파드는 Running, 실험은 무반응
- **말할 것** — socketPath 를 빼면 chaos-daemon 이 붙을 소켓이 없다
- **넘어가며** — 로그에 no such file or directory

### 10-06 주입한 지연 600ms, 알림은 3분 뒤

- **화면** — 실험 3 타임라인 4행
- **말할 것** — 그 3분은 for 가 만든 것이다
- **넘어가며** — 07장의 네 구간이 여기서 눈에 보인다

### 10-07 안전장치를 빼면 가설이 기각된다

- **화면** — replicas 1 로 줄인 뒤 파드 킬
- **말할 것** — 502 · 에러율 100% · AppHighErrorRate 발화
- **넘어가며** — 03장에서 심은 것들이 그것을 빼는 순간 증명된다

### 10-08 기각도 실험 성공이다

- **화면** — 시트 4번 칸
- **말할 것** — 몰랐던 취약점을 장애 전에 찾은 것
- **넘어가며** — 게임 데이의 채점 기준
