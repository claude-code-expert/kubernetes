# PPT 제작 규약

장표는 이 저장소에서 만들지 않는다. 별도 저장소가 이 디렉터리의 세 가지만 받아 제작한다.

| 파일 | 무엇 |
|---|---|
| `MANIFEST.json` | **장표 56개 ↔ 자산 매핑.** 여기부터 읽는다 |
| `outline.md` | 장표 단위 아웃라인. 제목 · 화면 · 말할 것 · 넘어가는 문장 |
| `notes/` | 장별 발표자 노트 11편. 장표 번호로 나뉘어 있다 |
| `figures/` | 도판. 문서에서 뽑은 SVG 21개 + 옛 슬라이드 PNG 5개 |
| `tables/` | 표 16개. TSV — 첫 줄이 머리행 |
| `snippets/code/` | 코드 8개. 장표용으로 이미 잘라 둔 것 |
| `snippets/output/` | 실행 결과 7개. 판정 줄에 표시가 붙어 있다 |
| `GUIDE.md` | 이 문서 |

`MANIFEST.json` 이 진입점이다. 장표 하나를 만들 때 그 항목의 `assets` 를 보면
어떤 도판·코드·출력·표를 쓸지 나온다. `gaps` 에 적힌 것은 아직 없는 자산이다.

정본은 `study/ch*.html` 열한 편이다. **문서가 먼저이고 장표가 나중**이다.
아웃라인과 문서가 어긋나면 문서를 기준으로 아웃라인을 고친다.

## 판형과 안전 영역

- 16:9, 1920×1080 기준
- 상하좌우 여백 각 80px. 이 안쪽만 내용이 들어간다
- 하단 120px 은 화면 아래쪽이 가려지는 강의실이 많으므로 비워 둔다
- 도판은 가로 1600px 이내. `figures/` 의 PNG 는 954px 폭이라 확대하지 말고
  필요하면 SVG 원본에서 다시 내보낸다

## 팔레트 — 문서와 공유한다

색을 새로 만들지 않는다. 아래 다섯 개로만 그린다.

| 역할 | 값 | 쓰는 곳 |
|---|---|---|
| 본문 | `#15181d` | 제목, 본문 |
| 보조 | `#585f6b` | 캡션, 라벨, 도판의 선 |
| 경계 | `#d8dbe0` | 표 테두리, 구분선 |
| 배경 | `#f5f6f7` | 코드 블록, 강조 박스 배경 |
| 강조 | `#1a4fa0` | 지금 말하는 것 하나 |
| 경고 | `#8f4408` | 함정, 정정, 실패 |

도판 안에서만 쓰는 색이 넷 더 있다. 흐름의 종류를 구분하는 데 의미가 실려 있어서
장표 본문 색과 별개로 둔다. 새 도판을 그릴 때 이 규칙을 따른다.

| 값 | 뜻 |
|---|---|
| `#6a4a9c` | 메트릭 수집(pull) 경로 |
| `#b4621a` | 로그 전송(push) 경로 |
| `#1f4d8f` | 질의 · 조회 경로 |
| `#2e7d4f` | 성공 · 정상 상태 |
| `#9aa1ad` | 비활성 · 배경 요소 |

강조색은 **한 장표에 한 번**만 쓴다. 두 곳을 강조하면 어느 쪽도 강조가 아니다.

## 타이포

- 본문 Pretendard, 코드 JetBrains Mono
- 제목 44pt / 본문 28pt / 코드 22pt / 캡션 18pt
- 뒷줄에서 읽히는 최소 크기가 22pt다. 그보다 작게 쓸 내용이면 장표에서 뺀다

## 발표자 노트

`notes/chNN.md` 가 장표마다 한 절씩 갖는다. 절 제목이 장표 번호(`## 04-03 …`)이므로
`MANIFEST.json` 의 `slides[].notes` 값(`notes/ch04.md#04-03`)으로 바로 찾아간다.

노트에 들어 있는 것 —

- **말할 것** — 아웃라인 한 줄을 발표 가능한 분량으로 편 것
- **질문이 나오면** — 스터디에서 실제로 나오는 물음과 답
- **함정 · 근거** — 문서가 정정하는 낡은 정보, 책의 절 번호

노트는 슬라이드에 넣지 않는다. 발표자 노트 영역에 넣거나 인쇄용으로 쓴다.
장표 본문에 노트를 옮겨 붙이면 "한 장표 한 주장"이 깨진다.

## 한 장표 한 주장

아웃라인의 "말할 것"이 두 문장을 넘으면 장표를 쪼갠다.
제목은 명사구가 아니라 **주장**으로 쓴다.

- 나쁨 — "ServiceMonitor 설정"
- 좋음 — "라벨 세 겹 중 하나만 어긋나도 에러 없이 타깃이 사라진다"

## 자산을 쓰는 법

`snippets/` 의 코드와 출력은 **이미 장표용으로 잘라 둔 것**이다. 더 줄이지 않아도 되고,
반대로 문서에서 전문을 다시 가져오지 않는다. 자를 때 판정 줄이 날아가기 때문이다.

출력 파일에는 `← 판정 줄` 또는 `판정 —` 로 어디를 강조할지 표시해 두었다.
그 줄에만 강조색(`#1a4fa0`)을 쓴다.

`tables/` 는 TSV 다. 첫 줄이 머리행이고 셀 안에 줄바꿈은 없다.
행이 많아 한 장표에 안 들어가면 **행을 줄이지 말고 장표를 쪼갠다** —
줄이면 그 표가 말하려던 대비가 사라진다.

## 코드

- 8줄 이하. 넘으면 핵심 줄만 남기고 `...` 로 줄이되 **줄었음을 표시**한다
- 전문은 실습 가이드 링크로 보낸다. 장표에 전문을 넣지 않는다
- 명령과 출력은 다른 블록으로 나눈다
- 프롬프트 기호(`$`)를 붙이지 않는다

## 실행 결과

- 터미널 전체를 붙이지 않는다. 붙이면 뒷줄에서 아무도 읽지 않는다
- **판정에 쓰는 줄만** 남기고 강조색으로 표시한다
- 환경마다 다른 값(파드 접미사, IP, 시각)은 그대로 두고 "환경마다 다르다"고 각주

## 금지

- 이모지
- 형광색, 그라데이션, 그림자
- 장점/단점 표를 기계적으로 붙이는 것. 선택의 근거만 쓴다
- 3개 이상 연속된 불릿으로 설명을 대신하는 것
- 지어낸 실행 결과. 확인하지 못한 출력은 넣지 않는다

`docs/이미지참고/` 의 기존 PNG 들이 이 규약과 어긋나는 사례다 — 형광 팔레트에
이모지가 섞여 있고 한 장에 네 가지를 설명한다. `study/ch*.html` 의 인라인 도판이
지켜지는 사례다.

## 도판

### 문서에서 뽑은 SVG 21개 (주력)

`study/ch*.html` 의 인라인 도판을 그대로 뽑은 것이다. 이름은 `chNN-figN.svg`,
문서의 그림 번호와 같다. 벡터라 확대해도 깨지지 않으므로 장표에는 이쪽을 쓴다.
캡션과 대체 텍스트는 `MANIFEST.json` 의 각 장 `figures` 에 들어 있다.

문서가 정본이므로 **도판을 장표에서 고치지 않는다.** 고쳐야 하면 문서를 먼저 고치고
다시 뽑는다.

### 아직 없는 도판 11개

`MANIFEST.json` 의 `gaps.figure` 에 장표 번호와 명세가 있다. 새로 그릴 때는
위 팔레트를 쓰고 흰 배경 · 모노스페이스 라벨을 지킨다.

### 옛 PNG 5종 (보조)

`figures/` 의 PNG 5종은 기존 슬라이드에서 쓰던 것이다.

| 파일 | 내용 | 쓰는 장 |
|---|---|---|
| `arch-observability-stack.png` | 관측 스택 아키텍처 | 04 |
| `seq-request-scrape.png` | 요청 → 스크레이프 시퀀스 | 02 · 06 |
| `dataflow-log-pipeline.png` | 로그 수집 파이프라인 | 08 |
| `lifecycle-alert.png` | 알림 발화·해소 상태 전이 | 07 |
| `workflow-redeploy.png` | 빌드 → 적재 → 배포 절차 | 03 |

같이 있는 `.json` 은 이 PNG 들을 만든 원본 명세다. 생성 도구(archify)가 현재
환경에 설치돼 있지 않아 **지금은 재생성할 수 없다**. 도판을 새로 만들어야 하면
`study/ch*.html` 안의 인라인 SVG 방식을 따른다 — 흰 배경, `#585f6b` 선,
모노스페이스 라벨.
