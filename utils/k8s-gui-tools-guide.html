쿠버네티스 실습 도구

kubectl 로 되는 일을 더 빨리 하거나, 눈으로 봐야 알 수 있는 것을 보기 위한 도구 셋. 터미널의 k9s, 브라우저의 Headlamp, 데스크톱의 Freelens 를 설치하고 같은 클러스터를 세 방식으로 본다.

01왜 도구를 따로 쓰나

kubectl 로 못 하는 일은 없다. 그런데 장애를 쫓을 때 하는 일은 대개 이런 모양이다 — 파드 목록을 보고, 하나를 골라 로그를 보고, 다시 목록으로 돌아와 다른 파드의 이벤트를 보고, 컨테이너에 들어가 본다. kubectl 로 하면 명령 네 줄과 파드 이름 복사·붙여넣기가 매번 필요하다.

세 도구가 각각 그 반복을 다르게 줄인다.

도구형태가장 잘하는 것못 하는 것
k9s터미널 (TUI)키 몇 번으로 목록 → 로그 → 셸. SSH 로 들어간 서버에서도 된다그래프·토폴로지 같은 그림
Headlamp브라우저 · 데스크톱클러스터 안에 띄워 팀이 같은 화면을 본다. RBAC 을 그대로 따른다터미널 작업 흐름과 섞기
Freelens데스크톱 앱여러 클러스터를 탭으로 오가며 보기. 내장 터미널클러스터 안에서 공유하기
셋 다 kubectl 을 대체하지 않는다

이 문서의 도구는 전부 같은 쿠버네티스 API 를 호출한다. 화면이 보여 주는 것은 kubectl get 이 보여 주는 것과 같은 데이터이고, 권한도 kubectl 과 같은 자격으로 판정된다. 도구가 보여 주지 않는 것은 대개 권한이 없어서다.

02알아야 할 개념

도구는 두 자리 중 하나에 선다

k9s 와 Freelens, 그리고 Headlamp 의 데스크톱판은 내 노트북에서 돈다. ~/.kube/config 를 읽어 내 자격으로 API 서버를 호출한다. 내가 볼 수 있는 것만 보인다.

Headlamp 는 클러스터 안에 띄울 수도 있다. 그러면 브라우저만 있으면 누구나 접속할 수 있고, 누구로 접속했는지는 붙여 넣은 서비스 계정 토큰이 정한다. 팀이 같은 주소를 보는 대신, 토큰이 곧 권한이라는 점을 관리해야 한다.

CPU·메모리 숫자는 별도 구성요소가 준다

세 도구 모두 파드의 CPU·메모리를 보여 주려 한다. 그런데 그 숫자는 쿠버네티스 API 가 기본으로 주는 것이 아니라 metrics-server 가 제공한다. 설치돼 있지 않으면 그 열만 비어 보이거나 대시가 뜬다 — 도구 문제가 아니다.

읽기 전용으로 여는 습관

세 도구 다 지우기·편집이 몇 키 안에 있다. k9s 는 ctrl-d 가 삭제고, GUI 는 버튼 하나다. 강의·데모·운영 클러스터를 남에게 보여 줄 때는 읽기 전용 모드로 여는 편이 안전하다.

이 문서를 마치면 할 수 있는 것

  1. 세 도구를 맥에 설치하고, 같은 클러스터를 세 방식으로 열 수 있다.
  2. k9s 에서 목록 → 로그 → 셸까지 손을 키보드에서 떼지 않고 이동할 수 있다.
  3. Headlamp 를 클러스터 안에 띄우고 서비스 계정 토큰으로 접속할 수 있다.
  4. 사용량 열이 비었을 때 도구가 아니라 metrics-server 를 의심할 수 있다.
  5. 남에게 화면을 보여 줄 때 읽기 전용으로 여는 방법을 안다.

03세 도구가 서 있는 자리

  • 1 지금 어느 클러스터를 보고 있나. 도구를 열기 전에 이것부터 맞춘다. 확인 kubectl config current-context
  • 2 내 권한이 어디까지인가. 도구의 버튼이 보이고 안 보이고가 여기서 갈린다. 확인 kubectl auth can-i --list -n default | head
  • 3 사용량 숫자가 나올 환경인가. 없으면 CPU·메모리 열이 빈다. 확인 kubectl top nodes → 숫자가 나오면 metrics-server 가 있다

5분 워크스루

# 네임스페이스를 지정해 바로 연다
k9s -n tools-demo
  1. :pod ⏎ — 파드 목록. 04절에서 만든 web-... 세 줄이 보인다
  2. /web ⏎ — 이름으로 거른다. 다른 네임스페이스 것이 섞여 있어도 걸러진다
  3. 커서를 하나에 두고 l — 로그. esc 로 돌아온다
  4. d — describe. 아래쪽 Events 가 장애 조사의 출발점이다
  5. s — 컨테이너 셸. exit 로 빠져나온다
  6. :deploy ⏎ 로 디플로이먼트 화면으로 옮긴 뒤, web 에 커서를 두고 ctrl-l(스케일)로 레플리카를 바꿔 본다
  7. :ctx ⏎ — 컨텍스트 목록. 클러스터를 바꿔 끼울 때 쓴다
  8. :q ⏎ — 종료
이게 k9s 의 요지다

1번부터 5번까지 파드 이름을 한 번도 타이핑하지 않았다. 같은 일을 kubectl 로 하면 매번 목록을 보고 이름을 복사해야 한다.

06Headlamp — 브라우저에서 함께 보기

Headlamp 는 CNCF 샌드박스 프로젝트이며 저장소는 kubernetes-sigs/headlamp 다. 데스크톱 앱으로도, 클러스터 안 웹으로도 쓸 수 있다. 팀이 같은 화면을 봐야 한다면 in-cluster 가 목적에 맞는다.

데스크톱 앱으로 쓰기

brew install --cask headlamp
# 나중에 올릴 때
brew upgrade headlamp

설치하면 /Applications 에 앱이 생기고, 실행하면 ~/.kube/config 의 컨텍스트가 목록으로 뜬다. 클러스터를 고르면 바로 연결된다 — 토큰을 따로 넣지 않는다.

옛 문서의 --no-quarantine 는 쓰지 않는다

예전 안내에 있던 brew install --cask --no-quarantine headlamp 는 지금은 에러가 난다. Homebrew 가 그 스위치를 막았고, 공식 문서도 접두사 없는 형태로 바뀌었다. 서명되지 않은 앱 경고가 뜨면 시스템 설정에서 한 번 허용하는 쪽으로 처리한다.

클러스터 안에 띄우기 (Helm)

helm repo add headlamp https://kubernetes-sigs.github.io/headlamp/
helm repo update headlamp
helm search repo headlamp/headlamp --versions | head -3

--- 출력 (버전은 확인일 기준) ---

NAME             	CHART VERSION	APP VERSION	DESCRIPTION
headlamp/headlamp	0.45.0       	0.45.0     	Headlamp is an easy-to-use and extensible Kuber...
headlamp/headlamp	0.44.0       	0.44.0     	Headlamp is an easy-to-use and extensible Kuber...
helm install headlamp headlamp/headlamp \
  --namespace kube-system \
  --version 0.45.0 \
  --wait --timeout 5m

kubectl -n kube-system get pods,svc | grep headlamp

--- 출력 (파드 접미사와 IP 는 환경마다 다르다) ---

pod/headlamp-6fd8cf44d5-dbkj4     1/1     Running   0     10d
service/headlamp   ClusterIP   10.96.196.194   <none>   80/TCP   10d
매니페스트로 설치하는 길도 있다

헬름을 쓰지 않는다면 공식 매니페스트 한 줄로도 된다. 값 조정이 필요 없을 때 쓴다.

kubectl apply -f https://raw.githubusercontent.com/kubernetes-sigs/headlamp/main/kubernetes-headlamp.yaml

접속과 토큰

목적: 서비스를 내 PC 로 잠시 끌어오고, 누구로 접속할지를 토큰으로 정한다.

kubectl -n kube-system port-forward svc/headlamp 8110:80

# 다른 터미널에서 — 떠 있는지부터 확인
curl -s -o /dev/null -w '%{http_code}\n' http://localhost:8110/

--- 출력 ---

200

브라우저로 http://localhost:8110 을 열면 토큰을 묻는다. 서비스 계정을 만들고 권한을 준 뒤 토큰을 발급한다.

kubectl -n kube-system create serviceaccount headlamp-admin

kubectl create clusterrolebinding headlamp-admin \
  --serviceaccount=kube-system:headlamp-admin \
  --clusterrole=cluster-admin

# 1.24+ 는 토큰을 이렇게 즉석 발급한다 (기본 만료 1시간)
kubectl create token headlamp-admin -n kube-system
cluster-admin 은 실습 편의다

위 바인딩은 클러스터의 모든 것을 할 수 있는 권한이다. 실습에서는 화면을 빨리 띄우려고 쓰지만, 팀에 열어 줄 때는 필요한 만큼만 주는 Role 을 따로 만든다. Headlamp 는 RBAC 을 그대로 따라서 권한이 없는 동작은 버튼 자체를 감춘다 — 읽기 전용 계정을 만들면 화면이 곧 읽기 전용이 된다.

발급된 토큰은 그대로 붙여 넣는 자격 증명이다. 화면 공유·채팅·문서에 남기지 않는다. 만료되면 같은 명령으로 다시 받는다.

07Freelens — 데스크톱 IDE

Freelens 는 Lens 의 오픈소스 판(OpenLens)을 이어받은 포크이고 MIT 라이선스다. 여러 클러스터를 탭처럼 두고 오가는 작업에 강하다.

설치

brew install --cask freelens
OS설치요구 사항
macOSbrew install --cask freelens · 또는 PKG/DMG (arm64 · amd64)macOS 12 이상
Windowswinget install Freelensapp.Freelens · scoop install freelensWindows 10 이상
Linuxsnap install freelens --classic · Flatpak · AppImage · APT · AURglibc 2.34 이상

클러스터 연결과 화면

실행하면 ~/.kube/config 의 컨텍스트를 읽어 카탈로그에 띄운다. 클러스터를 고르면 좌측에 트리가 열린다 — Workloads · Config · Network · Storage · Access Control · Custom Resources 순이다.

메뉴안에 있는 것
WorkloadsPods · Deployments · ReplicaSets · DaemonSets · Jobs · CronJobs
ConfigConfigMaps · Secrets · Resource Quotas · HPA
NetworkServices · Endpoints · Ingresses · Network Policies
StoragePVC · PV · StorageClass
Access ControlServiceAccounts · Roles · RoleBindings
Custom ResourcesCRD 로 추가된 리소스 — ServiceMonitor 같은 것이 여기 나온다
내장 터미널이 편하다

하단 터미널은 선택한 클러스터의 컨텍스트가 이미 맞춰진 셸이다. 컨텍스트를 잘못 잡고 명령을 치는 사고를 줄여 준다. 파드 화면의 셸 버튼은 컨테이너 안으로 바로 들어간다.

사용량 그래프가 비어 있다면

Freelens 의 CPU·메모리 그래프는 metrics-server 또는 프로메테우스에서 값을 가져온다. 둘 다 없으면 그래프 자리가 빈 채로 남는다. 클러스터 설정에서 메트릭 출처를 지정할 수 있고, 프로메테우스를 이미 쓰고 있다면(관측성 04장) 그쪽을 가리키면 된다.

# 먼저 클러스터에 값이 있는지부터 확인한다
kubectl top nodes
kubectl top pods -n tools-demo

09언제 무엇을 쓰나

상황고르는 도구이유
SSH 로 들어간 서버에서 조사k9s브라우저도 X11 도 필요 없다
로그 → 셸 → 다른 파드로 빠르게 이동k9s키 몇 번. 이름 복사가 없다
팀이 같은 화면을 봐야 함Headlamp (in-cluster)주소 하나를 공유한다. 권한은 토큰으로 나눈다
쿠버네티스를 처음 보는 사람에게 설명Headlamp · Freelens리소스 관계가 화면에 구조로 보인다
클러스터 여러 개를 오가며 작업Freelens카탈로그에서 바로 전환. 내장 터미널의 컨텍스트가 따라온다
CRD 가 많은 클러스터 둘러보기Freelens · HeadlampCustom Resources 메뉴에서 목록으로 본다
화면을 녹화·공유해야 함k9s --readonly실수로 지울 여지를 없앤다
하나만 고른다면

터미널에 익숙하면 k9s 하나로 대부분이 끝난다. 팀과 공유가 목적이면 Headlamp 를 클러스터에 띄우는 쪽이 값을 한다. Freelens 는 클러스터가 여러 개일 때 차이가 난다 — 하나뿐이면 앞의 둘과 크게 다르지 않다.

10자주 겪는 문제

증상원인과 조치
CPU·메모리 열이 비어 있거나 -metrics-server 가 없다. kubectl top nodes 로 먼저 확인한다 — 도구 문제가 아니다
목록이 비어 있고 에러도 없다네임스페이스가 좁혀져 있거나 권한이 없다. kubectl auth can-i list pods -n <ns>
도구가 엉뚱한 클러스터를 본다kubectl config current-context 확인. k9s 는 :ctx, GUI 는 전환기에서 바꾼다
k9s 화면이 흑백·깨짐export TERM=xterm-256color
k9s 에서 e 가 안 먹는다KUBE_EDITOR 미설정. export KUBE_EDITOR=vim
맥에서 앱이 “확인되지 않은 개발자” 로 막힘서명 문제다. --no-quarantine 는 이제 안 되므로 시스템 설정에서 한 번 허용한다
Headlamp 접속 후 아무 리소스도 안 보임토큰의 권한이 좁다. 계정에 맞는 Role 을 주거나 클러스터 설정에서 접근 가능한 네임스페이스를 지정한다
토큰이 곧 만료된다kubectl create token 의 기본 만료는 1시간이다. 필요하면 --duration 으로 늘리되 짧게 유지하는 편이 안전하다
포트포워드가 자꾸 끊긴다파드가 재시작하면 끊긴다. 상시로 열어야 하면 Ingress·Gateway 뒤에 둔다
