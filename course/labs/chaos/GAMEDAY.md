# 게임 데이 실험 시트 (M36)

실험 하나에 시트 하나. **가설을 먼저 쓰고 나서 주입한다** —
주입하고 나서 결과를 보고 가설을 쓰면 그것은 관찰이지 실험이 아니다.

## 실험 #1 — 파드가 갑자기 사라진다

| 항목 | 내용 |
|---|---|
| 날짜 / 담당 | 2026-09-06 |
| 정상 상태 정의 | 부하 158 req/s 에서 실패 응답 0건, P95 < 50ms |
| 가설 | journal-api 파드 하나가 죽어도 **실패 요청은 0** 이다 |
| 근거 | M15 preStop 10초 + 프로브 3종, M17 PDB minAvailable 2 |
| 폭발 반경 | journal 네임스페이스 · journal-api 파드 1개 (`mode: one`) |
| 중단 조건 | 실패율 5% 초과 또는 인그레스 5xx 발생 시 즉시 실험 삭제 |
| 주입 | `kubectl apply -f chaos/10-podchaos.yaml` |
| 대조 | 주입 직전 20초의 코드 분포와 비교 |
| 실측 | 요청 10,236건 / 200: 10,236 / 실패 0 |
| 판정 | **가설 성립** |
| 배운 것 | preStop 없이 M15 에서 쟀을 때는 20건이 떨어졌다. 그 차이가 이 실험의 값이다 |

## 실험 #2 — 레디스가 느려진다 (통신 카오스)

| 항목 | 내용 |
|---|---|
| 정상 상태 정의 | /api/entries 응답 1~2ms |
| 가설 | 레디스로 가는 경로에 200ms 지연을 넣으면 **응답은 느려지지만 실패는 없다** |
| 폭발 반경 | journal-api → redis 방향만. 다른 통신은 건드리지 않는다 |
| 주입 | `chaos/20-networkchaos.yaml` (delay 200ms, 60초) |
| 실측 | 응답 1.5ms → **404ms**. 실패 0건 |
| 판정 | 가설 성립. 다만 404ms 는 200ms 의 **두 배** — 앱이 레디스를 요청당 2회 부른다는 뜻 |
| 배운 것 | 지연 실험이 **호출 횟수를 드러낸다.** 코드를 읽지 않고 알아낸 사실이다 |

### 실험 #2-b — 지연이 타임아웃을 넘으면

| 항목 | 내용 |
|---|---|
| 가설 | 지연이 클라이언트 타임아웃(2초)을 넘으면 실패가 나타난다 |

## 실험 #3 — CPU 가 고갈된다 (작동 카오스)

| 항목 | 내용 |
|---|---|
| 가설 | 파드 하나의 CPU 를 태우면 ① HPA 가 늘리고 ② 실패는 없다 |
| 폭발 반경 | journal-api 파드 1개 (`mode: one`), 90초 |
| 주입 | `chaos/30-stresschaos.yaml` (cpu workers 2, load 100) |
| 실측 | HPA 33% → **1051%** → 파드 4 → 8 (max). 요청 18,756건 전부 200 |
| 판정 | 가설 성립 |
| 배운 것 | **HPA 는 평균을 본다.** 파드 하나가 2022m 을 쓰자 나머지 7개가 놀고 있는데도 전부 늘었다. 한 파드의 이상이 클러스터 자원을 8배로 쓰게 만든다 |

## 실험 #4 — 애플리케이션이 오류를 낸다

| 항목 | 내용 |
|---|---|
| 가설 | 에러율이 50% 가 되면 M21 의 `AppHighErrorRate` 알림이 **2분 안에** 발화한다 |
| 주입 | `journal-api:v3` + `FAULT_RATE=0.5` (M30 에서 만든 손잡이) |
| 실측 | 요청 7,153건 중 500: 3,537 (49.5%) · 에러율 쿼리 48.6% |
| 알림 | `AppHighErrorRate firing journal-api — journal-api 에러율 35.5%` |
| 판정 | **가설 성립.** 알림 경로가 실제로 동작한다 |
| 배운 것 | HTTPChaos 로 연결을 끊었을 때는 이 알림이 **울리지 않았다** — 요청이 앱에 도달하지 못해 메트릭이 기록되지 않기 때문이다. **알림은 관측 지점 뒤의 고장만 본다** |

## 게임 데이 4단계 요약

1. **가설** — 정상 상태를 숫자로 정의하고, 무엇이 일어날지 먼저 쓴다
2. **이벤트** — 폭발 반경과 중단 조건을 정한 뒤 주입한다
3. **대조** — 주입 전후를 같은 측정 도구로 비교한다
4. **판정** — 가설이 맞았는지 적고, **틀렸으면 왜 틀렸는지**를 적는다

## 스테이징에서 재현되지 않는 것

- 실제 트래픽 양과 분포 (실험 #3 의 HPA 반응은 부하가 있어야 나온다)
- 실제 데이터 크기 (레디스에 엔트리가 3건일 때와 300만 건일 때가 다르다)
- 실제 노드 수와 배치
- 실제 사용자의 재시도 행동 (실패하면 사람은 새로고침을 누른다 — 부하가 늘어난다)
- 외부 의존성의 실제 지연과 장애
- 시간 (며칠에 걸쳐 새는 메모리는 30분 실험에서 안 보인다)
